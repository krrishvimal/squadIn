🎯 2. UX Philosophy: The "Zero-Confusion" Rule for Users Simplicity First
1. Glanceable Cards

Every plan shows: Category Icon, Time, Venue neighborhood, and Progress bar (e.g. 3/4 spots filled).

2. The 4-Tab Bottom Bar

Strictly 4 tabs: Explore (Feed), My Crews (Active plans), Chats (Unlocked), Profile (Trust badges).

3. One-Tap Actions

1-tap to Join, 1-tap Fast Unlock (₹49), 1-tap Invite Friend (+1). Zero complex sub-menus.

📱 3. Screen-by-Screen Interaction Specification 5 Screens Total
Screen 1: Explore Feed (Home)

• Top Filter Pills: All, ☕ Cafes, 🏸 Sports, 🎵 Concerts, 🚺 Women-Only.
• Plan Cards: Displays Title, Time, Distance (e.g. '1.2 km away'), Host verified badge, and live slot counter (e.g. [■■■□] 3/4 Filled).
• FAB (Floating Button): '➕ Post a Plan'.

Screen 2: Plan Details Modal

• Map Snapshot: Verified public cafe/venue location.
• Attendee Bubbles: Photos with Trust Badges (Work / ID Verified).
• Main Action: Large primary button 'Request Spot (Free)'.
• Deadlock Breaker: Secondary button '⚡ Fast-Unlock for ₹49'.

Screen 3: Post a Plan (3-Step Modal)

• Step 1 (Category): Selecting 'Dinner' auto-sets capacity to 4; 'Concert' auto-sets to 6; 'Trek' auto-sets to 8.
• Step 2 (Venue): Google Places search restricted to public commercial cafes, turfs, malls, parks. (Private homes blocked).
• Step 3 (Safety): Toggle: 'Women-Only' or 'Balanced Mixed'.

Screen 4: Group Chat (The Magic Screen)

• State A (Locked): Grayed-out chat with countdown progress bar + 'Fast-Unlock' button.
• State B (Unlocked): Full real-time messaging, icebreaker prompt, in-chat '+1 Invite Friend' button, and top 1-Tap SOS Share.

Database Schemas, State Triggers & Hardware Hooks

Complete copy-pasteable PostgreSQL schema, auto-unlock trigger, and native hardware integration code.

🗄️ 5. Supabase PostgreSQL Schema (Copy-Pasteable) Database
CREATE TABLE profiles ( id UUID REFERENCES auth.users PRIMARY KEY, full_name TEXT NOT NULL, avatar_url TEXT, work_email_verified BOOLEAN DEFAULT FALSE, id_verified BOOLEAN DEFAULT FALSE, karma_rating DECIMAL(2,1) DEFAULT 5.0, created_at TIMESTAMPTZ DEFAULT NOW() ); CREATE TABLE plans ( id UUID DEFAULT gen_random_uuid() PRIMARY KEY, host_id UUID REFERENCES profiles(id), title TEXT NOT NULL, category TEXT NOT NULL, -- 'cafe', 'concert', 'sports', 'hike' target_capacity INT NOT NULL, -- e.g. 4 for cafe, 6 for concert current_capacity INT DEFAULT 1, venue_name TEXT NOT NULL, venue_lat DOUBLE PRECISION, venue_lng DOUBLE PRECISION, event_time TIMESTAMPTZ NOT NULL, status TEXT DEFAULT 'OPEN', -- 'OPEN', 'LOCKED_CHAT_ACTIVE', 'COMPLETED' women_only BOOLEAN DEFAULT FALSE ); CREATE TABLE messages ( id UUID DEFAULT gen_random_uuid() PRIMARY KEY, plan_id UUID REFERENCES plans(id), sender_id UUID REFERENCES profiles(id), content TEXT NOT NULL, created_at TIMESTAMPTZ DEFAULT NOW() );
⚡ 6. PostgreSQL Auto-Unlock Function & Trigger (The Game Engine) Auto-Trigger
-- Automatically unlocks chat when capacity is full or fast-unlocked CREATE OR REPLACE FUNCTION check_plan_capacity_and_unlock() RETURNS TRIGGER AS $$ BEGIN IF NEW.current_capacity >= NEW.target_capacity THEN UPDATE plans SET status = 'LOCKED_CHAT_ACTIVE' WHERE id = NEW.id; END IF; RETURN NEW; END; $$ LANGUAGE plpgsql; CREATE TRIGGER trigger_plan_auto_unlock AFTER UPDATE OF current_capacity ON plans FOR EACH ROW EXECUTE FUNCTION check_plan_capacity_and_unlock();
